## 1. 产品与角色边界

openGym 是个人训练计划、训练执行和进展追踪工具。此目录采用 React 19 + Zustand + HashRouter，使用 Capacitor 封装 iOS/Android；iOS 不是独立 SwiftUI 页面实现。产品名称取代码中的 openGym。

| 角色/模式 | 可见能力与边界 |
|---|---|
| 本地使用者 | 移动端首次启动选择本设备使用，管理本地计划、训练、体重等数据 |
| 已连接用户 | 在个人功能基础上同步自建服务器；账户与连接状态依环境显示 |
| Web 访客 | 服务器允许时无需账户使用；与移动端首次启动的本地模式区分 |
| 管理员 | user.admin 才可访问 /admin；用户、邀请码、活动记录、教练配置等管理 |
| AI 教练 | 辅助能力而非独立登录角色；移动端自带 Key 模式，或服务器已启用教练且用户已连接 |

端侧分工：iOS 完成建计划、训练记录、统计与本地设置；Web 已登录账户可生成移动端配对码，手机录入服务器地址和配对码完成连接。管理员能力来自服务器账户权限，不默认要求在 PC 才能使用。不存在代码证据支持的“教练派单—学员审批”业务。

## 2. 模块树

- 入口：启动加载 → 移动端首次使用（本地 / 连接服务器）；Web 登录、注册、通行密钥、可选密码、其他设备代码。
- 首页：周日历或轮转队列、今日训练/恢复训练、首次建计划引导、体重与目标、健身房二维码入口、设置。
- 计划：日程 / 训练方案；固定周 / 轮转；方案编辑、动作配置、日期安排、入门计划、导入导出。
- 训练：选择训练 → 可选称重 → 逐组记录 → 组间休息 → 完成汇总；支持自由训练、组合方案、补录和历史编辑。
- 统计：训练活跃、动作进展、肌肉量/疲劳/力量、体重、历史、身体围度、结构平衡、进展照片。
- 动作库：搜索与筛选、收藏、自定义动作、肌肉浏览、动作说明/媒体/历史、加入方案。
- AI 教练：启用与提供商配置、知情同意、训练需求问卷、对话、计划建议、修改建议、复盘与建议历史。
- 设置与管理：训练、计时提醒、通知、计划、单位语言、器械、外观、数据备份、账户、关于、高级微调、管理员。

## 4. P0 组件与弹层清单

- 公共：底部五入口导航、页面标题与返回、卡片、分组行、分段控制、按钮、输入/步进器、筛选 Chip、Sheet、居中确认、Toast、同步状态条。
- 计划：方案行、周日历/日期分配、轮转队列、动作选择器、ExConfig 动作配置、入门方案选择器。
- 训练：动作卡片、组记录行、超级组、重量与次数/时长/有氧输入、完成勾选、努力度选择、动作/组/整次备注、休息倒计时、结束菜单、放弃确认、完成汇总。
- 查看：曲线、热图、肌肉图、训练历史行、动作说明与媒体。
- 组记录变体：力量、徒手、计时、有氧、左右侧、热身、超级组、递减/休息暂停、力竭标记。首轮先完整建立力量主链路，其余作为变体补齐。
- 训练布局：cards / list / compact / focus。训练进行中 /coach 对话与首次引导隐藏底部导航；恢复训练从其他页面进入。

状态规范：对有异步加载或远端请求的页面补 Default / Loading / Error；对列表与统计补 Empty；纯本地表单使用校验与保存反馈，不人为添加网络加载状态。破坏性操作、撤销、未保存离开、计时结束分别设计。

## 5. 核心业务流矩阵

| 流程 | 页面/端侧步骤 | 闭环与逆向路径 |
|---|---|---|
| 首次本地训练 | iOS 引导 → 本地模式 → 首页空态 → 入门计划或计划编辑 → 方案动作配置 → 排期 → 首页今日训练 → 可选称重 → 训练 → 完成汇总 → 首页/统计 | 无计划可自由训练；称重可跳过；没有完成组/提前结束需明确提示 |
| 常规训练 | 首页今日训练/中央开始 → 今日方案（可组合）→ 称重 → 逐组完成 → 休息 → 下一组/动作 → 完成 | 可返回其他页，再恢复；完成全部组后可继续加动作；放弃走确认 |
| 更换训练 | 首页“选择其他训练” → 开始选择器 → 其他方案或自由训练 → 训练 | 与首页直接启动今日方案区分；已有活动训练先恢复 |
| 计划维护 | 计划 → 方案列表 → 新建/编辑 → 动作选择 → 组数/次数/渐进配置 → 排序/超级组 → 固定周或轮转 | 删除可撤销；切回固定周需要说明进行中的轮转处理 |
| 历史修正 | 统计 → 历史 → 训练详情 → 编辑或补录 → 复用训练界面 → 保存 → 历史/统计 | 离开编辑需保存决策；补录不使用实时训练时钟/休息流程 |
| 身体追踪 | 首页/统计 → 体重或身体围度 → 记录 → 历史与曲线 → 目标变化 | 日期/数值校验；空历史与数据不足分别呈现 |
| 设备同步 | Web 已登录账户 → 生成移动配对码 → iOS 连接地址+代码 → 合并本机数据选择 → 连接状态 | 失败原地重试、失效重新配对；本地与服务器数据保留语义需可见 |
| AI 计划建议 | iOS 设置 → 服务器教练或自带 Key → 同意/问卷 → 对话请求 → 建议预览 → 采纳/拒绝 → 计划 → 训练 → 复盘 | 功能关闭/无服务隐藏入口；生成失败可重试；陈旧建议与部分采纳独立状态 |
| 到馆出示卡 | 首页 → Check in → 扫码/导入图片 → 保存二维码 → 出示 | 非二维码或无法识别报错；新用户显示无卡空态 |

## 6. Figma 组织与画板规格（建议）

目标文件原为空白，无既有组件；现已按确认架构建立 7 个 Page。

| Page 建议 | 内容 |
|---|---|
| 00_Flow & Spec | 来源、角色边界、模块树、页面矩阵、主流程、状态与权限注释 |
| 01_Design Tokens | 代码现有深浅主题、语义色、字阶、圆角、间距、安全区、动效参数 |
| 02_Components | 公共组件、导航、计划/训练/数据可复用组件及状态变体 |

| 04_Screens | P0 入口、首页、计划、动作选择/配置、训练、完成、统计、动作库 |
| 05_Extensions | P1/P2 历史、体征、签到、AI、照片、结构平衡 |
| 06_Settings & Admin | P3 设置、账户与管理员；条件能力明确标记 |

移动主规格 390 × 844；长内容使用可滚动框架并标注固定导航与安全区。Web 配对/管理可选 1440 × 900，只整理代码已有职责。首轮建议用简体中文、浅色主题；深色模式沿用代码变量，随后补核心页面变体（此主题/语言为建议，待确认）。

代码已有设计基础：dark 背景 #000000、卡片 #1c1c1e、绿色 #30d158；light 背景 #f2f2f7、卡片 #ffffff、绿色 #34c759。圆角 8/12/16/22，卡片 14，页面 padding 16，动效 140/220ms。品牌强调色可配置，绿色是默认，不锁死所有账户。

建议首个样板：HOM-01 有今日计划状态；用于验证导航、日历、卡片、体重曲线和主要操作。之后优先 WKT-02 力量训练状态，建立训练组件再展开其余页面。

## 7. 实施边界与后续核对

1. 本稿按现有代码还原业务；建议第一轮以 iOS 为主，Web 只保留配对上下文。是否需要全量管理端，确认时可调整。
2. AI 教练不是所有用户默认可用；需要启用/关闭、服务器未启用、自带 Key 三类条件说明。
3. Health Connect 代码明确仅 Android，iOS 返回 unsupported；Apple Health 出现在数据导入文案中，不能当作 iOS 原生健康同步已实现。
4. ProgressPhotos 当前添加入口关联当日训练；没有当日训练时先引导记录训练。
5. 设置页可见性依 mobile、user、权限及设备能力变化，不把 12 个页面键视为所有设备同时可见。
6. 未运行 App，暂不声称像素还原；实际文字换行、键盘/安全区、原生权限和媒体显示需在后续样板阶段核对。
7. 已检查 Figma 文件结构与编辑权限；使用已确认可用的 Noto Sans SC。后续样板阶段再建立实际组件与界面。
